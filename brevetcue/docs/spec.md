# ブルベ用キューシート自動生成サイト 仕様書

## 1. 背景・目的

現在、ブルベ（ACP公認ロングライド）の詳細キューシートは、以下の手順を **手動（AIとの対話）** で毎回行っている。

1. 主催者配布のExcelキューシート（PC・通過チェックの距離／Open・Close時刻）を読み込む
2. 主催者配布のGPXファイル（RideWithGPS等）を読み込み、曲がり角ごとの座標・進行方位を算出
3. 上記2つを突き合わせて、曲がり角ごとの緯度経度を特定
4. iPhoneで見やすい単一HTMLファイル（オフライン動作、ダークモード対応、天気・地図パネル付き）を生成

この一連の処理を **Webアプリとして自動化** し、GPXとExcel（またはPDF）をアップロードするだけで完成品HTMLが得られるようにしたい。

## 2. 想定ユーザー・利用シーン

- ブルベ主催者スタッフ（試走・下見用に詳細版を使う）
- ブルベ参加者（簡易版でPC/通過チェックの距離とClose時刻を確認する）
- 開催都度、複数のブルベ（200km〜1000km、スタート時刻も6:00〜早朝深夜まで様々）で使う

## 3. 入力データ

### 3.1 GPXファイル（ほぼ標準化されている）

RideWithGPSエクスポートのGPXが主。構造は概ね共通：

```xml
<gpx>
  <wpt lat="..." lon="...">
    <n>PC1セイコーマート木古内</n>   <!-- POI名（PC/通過チェックの場合あり） -->
    <cmt>convenience_store</cmt>
    <type>store</type>
  </wpt>
  ...
  <trk><trkseg>
    <trkpt lat="..." lon="...">
      <ele>25.9</ele>
    </trkpt>
    ...（数千〜2万点）
  </trkseg></trk>
</gpx>
```

- `trkpt`列から**累積距離**を計算できる（Haversine距離の積算）
- `wpt`にPC/通過チェックの名前が入っていることがあるが、**曲がり角の詳細（道路名・ランドマーク）は含まれない**
- トラックポイント間隔は平均15m程度（密）だが、疎密のばらつきあり

### 3.2 Excelキューシート（主催者ごとに形式が大きく異なる）

これまで扱った実例で、以下のようなバリエーションがあった：

| 項目 | パターン例 |
|---|---|
| シート構成 | 1シートのみ／「簡易キューシート」＋「詳細キューシート」の2シート／説明資料シート付き |
| 距離の単位 | 区間距離と積算距離が別列／積算距離のみ |
| 時刻の形式 | Excelシリアル値（0.291666=07:00）／`12日 08:12`のような文字列／複数日にまたがる場合は日付込みシリアル値（46208.005...） |
| Open/Close | 両方明記／Closeのみ／通過チェックはOpen/Closeなし（写真判定のみ） |
| 曲がり角情報 | 「進路」「道路種別」「備考」列がある場合とない場合 |
| PC/通過チェックの種別 | PC（レシート）／通過（写真）／通過（クイズ回答）の3種 |

**この形式のばらつきが自動化最大のネック。** 完全自動より「列マッピングを毎回軽く確認する」設計が現実的。

### 3.3 （オプション）出走日・想定速度

ユーザーがサイト上で入力：
- 出走日・出走時刻
- 想定巡航速度（10〜30km/h、1km/h刻み）
- 距離補正オフセット（試走中にサイコン実測とズレた場合の調整用）

## 4. 出力仕様（既存プロトタイプの仕様を踏襲）

添付の `brm912_hakodate300_detail.html` を参考実装とする。主な要件：

### 4.1 全体構成
- 単一HTMLファイル（オフラインで完全動作、GPX/Excelの解析結果は生成時にHTML内にインライン化）
- ナビタブで「簡易版」「詳細版」を切り替え（別ファイルまたは同一ファイル内タブ）

### 4.2 簡易版
- PC・通過チェック・Start/Goalのみ表示
- 各地点：距離／Open・Close時刻／ETA（速度に応じて自動計算）
- ETAはClose余裕に応じて色分け（余裕2h超＝青、30分〜2h＝緑、30分未満・超過＝赤）
- 上部バナーに速度ステッパー（10〜25km/h、1km/h刻み）
- 宿泊ポイントを追加可能：滞在時間ステッパー（0〜24h）でその地点以降のETAを一括シフト

### 4.3 詳細版
- 全ての曲がり角を表示（進路アイコン、信号有無、道路名、ランドマーク備考）
- **ETA計算は行わない**（Open/Closeのみ表示、速度非依存）
- 文字サイズは视认性重視で統一（本文はすべて同一サイズ・同一色、色の使い分けは最小限に）
- **ダークモード対応必須**：`prefers-color-scheme: dark`のメディアクエリでOS設定に自動追従
  - ライトモード：白背景・黒文字
  - ダークモード：黒背景・白文字、CP行は淡色背景をやめて左端の太いカラーボーダーのみで種別区別
  - 埋め込み地図はダークモード時に`filter: invert(...)`で反転
- 距離補正ステッパー（±0.1km/±1km、リセットあり）。ミスコース時にサイコン実測値と合わせるため、変更すると全地点の距離表示が一斉に更新される

### 4.4 天気・地図パネル（詳細版のみ、任意でタップ展開）
- 各地点に「🌤 天気・地図」トグルボタン。タップして初めて通信（無駄な読み込みを避ける）
- 地図：OpenStreetMap埋め込み（`https://www.openstreetmap.org/export/embed.html?bbox=...`）、該当座標にピン
  - 縮尺はbbox幅0.005°×0.003°程度（曲がり角の判別ができる拡大率）
- 天気：[Open-Meteo](https://open-meteo.com/) 無料API（CORS許可済み、APIキー不要）
  - `https://api.open-meteo.com/v1/forecast?latitude=...&longitude=...&hourly=temperature_2m,precipitation,windspeed_10m,winddirection_10m&timezone=Asia%2FTokyo&forecast_days=16`
  - ETA時刻に最も近い時間の気温・風向・降水量を表示
  - GPXから算出した進行方位と風向を比較し「↑向かい風／↓追い風／→横風」を表示
  - 予報範囲外（開催16日超前）の場合はその旨を表示し地図のみ出す

### 4.5 座標マッチングアルゴリズム（精度が重要）

Excelの距離値からGPX上の座標を求める際、**単純な最近傍探索ではなく線形補間**を使うこと。

```
1. トラックポイント列から累積距離配列 cum_dist[] を作る（Haversine距離の積算）
2. Excel記載の総距離とGPX総距離の比率でスケール補正
   scale = excel_total_distance / gpx_total_distance
3. 目的距離 d に対し、d/scale がGPXのどの区間 [cum_dist[i-1], cum_dist[i]] に入るか二分探索
4. その区間内で線形補間して緯度経度を算出
5. 進行方位（bearing）はその地点の前後15〜20点を使って算出
```

この方式で、最近傍スナップ方式に比べ平均誤差を数百m→数十m程度まで改善できることを確認済み。

## 5. アーキテクチャ提案

- **完全に静的なWebアプリ**（バックエンド不要）
  - GitHub Pages / Cloudflare Pages 等で無料ホスティング
  - ユーザーのファイルは全て端末内（ブラウザ内）処理、外部送信しない（route-weather.jpと同じ方針。プライバシー面でも安心）
- **GPX解析**：ブラウザ標準 `DOMParser` でXMLパース。追加ライブラリ不要
- **Excel解析**：[SheetJS (xlsx.js)](https://sheetjs.com/) をCDN経由で利用
- **列マッピングUI**：Excel読み込み後、シート・列を自動推測しつつ、以下を確認する簡易画面を挟む
  - どの列が「地点名」「積算距離」「Open」「Close」か
  - PC／通過チェック（写真）／通過チェック（クイズ）の判定方法（列の値 or 地点名のキーワード）
  - 日付をまたぐ場合の基準日
- **HTML生成**：本仕様書4章のテンプレートをJSのテンプレートリテラルで組み立て、Blobとしてダウンロードさせる（`<a download>`）
- **天気・地図機能**：生成されたHTML内に埋め込み、生成時ではなく閲覧時に都度取得（4.4節参照）

## 6. フェーズ分割（推奨）

一気に全部作ると破綻しやすいので、以下の順で進めることを推奨：

**Phase 1: GPXのみでMVP**
- GPXをアップロード→トラック情報（距離・座標・bearing）を抽出
- 手動で用意したJSON形式の曲がり角リスト（現状ClaudeがPython/正規表現で組み立てているデータ）を読み込ませて、4章のHTMLテンプレートで出力できることを確認
- ここでHTML生成テンプレート（CSS変数・ダークモード・天気/地図パネル）をモジュール化する

**Phase 2: Excel読み込み＋列マッピングUI**
- SheetJSでExcelを読み込み、シート一覧・セル内容をプレビュー表示
- ユーザーが列を指定 → PC/通過チェック/Open/Close/距離のデータ構造に正規化
- 時刻のシリアル値／文字列混在に対応するパーサーを実装（本仕様書3.2節のバリエーションに対応）

**Phase 3: GPX×Excel自動マッチング**
- 5章のアルゴリズムで、Excelの各距離値に対応する座標を算出
- 生成されたHTMLをその場でプレビュー＋ダウンロード

**Phase 4: 曲がり角の自動抽出（発展）**
- Excelに曲がり角情報がない場合、GPXのbearing変化点から「直進／右折／左折」を自動検出するアルゴリズムを追加
- ただし道路名・ランドマーク注記は自動生成できないため、この場合は「進路とアイコンのみ」の簡易な詳細版になる旨を明示

## 7. 既知の制約（重要）

- **道路名・ランドマーク注記はExcelの自由記述に依存**するため、Excelにこの情報がない場合は自動生成できない
- 天気予報は開催の**概ね16日前**からしか取得できない（Open-Meteoの仕様）
- 地図・天気機能は**閲覧時にネット接続が必要**（キューシート本体はオフラインで見られるが、これらのパネルはネットが要る）
- 主催者のExcel形式は今後も新しいパターンが出てくる可能性が高く、列マッピングUIは「ある程度の手動確認」を前提にした方が破綻しにくい

## 8. 参考にした既存サービス

- [Route-Weather.jp](https://route-weather.jp/)：GPX＋出走時刻からコース上の天候（風・雨・気温）を表示するブルベ向けサービス。天気取得のUXと「端末内処理・外部送信なし」の方針を参考にした
